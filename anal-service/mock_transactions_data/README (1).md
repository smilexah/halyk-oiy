# 🏦 Halyk Bank — Transaction Analytics Pipeline

Проект для автоматической обработки банковских выписок Halyk Bank: от сырых до структурированной базы данных со статистикой по расходам.

---

## Быстрый старт

```bash
pip install pdfplumber pandas numpy
jupyter notebook halyk_etl.ipynb
```

Запускай ячейки сверху вниз — каждая следует из предыдущей.

---

## Структура проекта

```
halyk_etl.ipynb          — главный ноутбук (ETL pipeline)
halyk_bank.db            — SQLite база данных (создаётся при запуске)
halyk_raw/               — сырые CSV после извлечения из PDF
final_transactions.csv   — очищенные транзакции
final_stats.csv          — avg & median по user_id × category
final_user_summary.csv   — сводка по каждому пользователю
```

### Ячейка 2 — Transform (очистка и нормализация)

Самая важная ячейка. Решает три основные проблемы сырых данных:

**Проблема 1 — мусорные строки**

Выписка содержит пустые строки-разделители и повторяющиеся заголовки `"Дата"` на каждой странице. Всё это удаляется.

**Проблема 2 — два разных формата суммы**

| Формат | Пример | Как парсится |
|--------|--------|--------------|
| Новый (карточные операции) | `-10,346.78 ₸` | запятая = разделитель тысяч, точка = десятичная |
| Старый (переводы/выписка) | `- 10 000,00 ₸` | пробел = разделитель тысяч, запятая = десятичная |

Функция `parse_amount()` определяет формат по наличию точки и запятой, затем возвращает `abs()` — все суммы всегда положительные.

**Проблема 3 — два формата даты**

`30.05.2026` (новый) и `30.05.26` (старый) — оба обрабатываются через `datetime.strptime`.

**Что добавляется в датафрейм:**

| Колонка | Описание |
|---------|----------|
| `date` | Дата транзакции (datetime) |
| `amount` | Сумма в тенге, всегда положительная |
| `amount_raw` | Исходная строка суммы (для отладки) |
| `operation_type` | Нормализованный тип: `purchase`, `transfer`, `topup`, `payment`, `misc` |
| `direction` | `debit` (расход) или `credit` (поступление) — определяется по знаку `-` в исходной строке |
| `user_id` | ID пользователя (случайно назначается из 10 вариантов) |
| `category` | Категория расхода (случайно назначается из 25 вариантов) |

### Ячейка 3 — Aggregate (статистика)

На основе очищенного `transactions` считаются две агрегированные таблицы.

**`stats` — по каждой комбинации `user_id × category`:**

| Колонка | Описание |
|---------|----------|
| `count` | Количество транзакций |
| `total` | Общая сумма расходов |
| `avg` | Средний чек |
| `median` | Медианный чек |
| `min_amount` | Минимальная транзакция |
| `max_amount` | Максимальная транзакция |

**`user_summary` — сводка по каждому пользователю:**

| Колонка | Описание |
|---------|----------|
| `total_transactions` | Всего транзакций |
| `total_spent` | Суммарные расходы |
| `avg_transaction` | Средний чек |
| `median_transaction` | Медианный чек |

### Ячейка 4 — Load (загрузка в SQLite)


```
db
├── transactions    — все очищенные транзакции
├── stats           — avg & median по user_id × category
└── user_summary    — сводка по пользователям
```


```python
import sqlite3, pandas as pd

conn = sqlite3.connect("")

# Топ категорий по расходам
df = pd.read_sql("""
    SELECT category,
           COUNT(*)              AS cnt,
           ROUND(SUM(amount), 0) AS total,
           ROUND(AVG(amount), 2) AS avg
    FROM   transactions
    WHERE  direction = 'debit'
    GROUP  BY category
    ORDER  BY total DESC
    LIMIT  10
""", conn)

conn.close()
```

## Схема данных

```
transactions
│
├── transaction_id  INTEGER   первичный ключ
├── date            TEXT      дата операции
├── amount_raw      TEXT      сырая строка суммы
├── amount          REAL      сумма (всегда > 0)
├── operation_raw   TEXT      тип операции (оригинал)
├── operation_type  TEXT      нормализованный тип
├── direction       TEXT      'debit' | 'credit'
├── details         TEXT      детали / получатель
├── Мерчант         TEXT      название мерчанта (если есть)
├── user_id         TEXT      ID пользователя
└── category        TEXT      категория расхода
```

## Известные ограничения

- `user_id` и `category` назначаются **случайно** — в реальном проекте их нужно определять по логике (мерчант → категория, номер карты → пользователь).
- Суммы в иностранной валюте (например, `- 57 233,24 ₸ (- 116,00 USD)`) парсятся только в тенге; долларовая часть отбрасывается.
- Если структура PDF-выписки изменится (новый шаблон Halyk Bank), может потребоваться корректировка порядка колонок в ячейке 2.
